# IntelliDesk — 基于 Adaptive-RAG 的多智能体电商客服 Agent

> 从零构建的完整 Agent 产品，覆盖多智能体架构、自适应检索、MCP 协议、多模态识别、流式交互全链路。

---

## 一、项目背景与痛点

针对传统 FAQ 客服系统**长尾问题命中率低**、人工介入成本高的问题，以及常规 RAG **多跳推理能力差**、**幻觉问题严重**的痛点，设计并实现了基于 Adaptive-RAG 的多智能体电商客服系统。

---

## 二、多智能体架构设计

基于 **LangGraph** 搭建核心 Agent 状态机，实现**规划器-执行器**分离架构：

- **意图路由**：采用 Prompt-template + DeepSeek 构建 7 类意图分类节点（订单/售后/商品/物流/支付/账号/综合），LLM 自主决策分类，100 条测试 query 意图识别准确率 **97%**
- **专业子 Agent**：每类意图配备独立 System Prompt + 推荐工具集，实现领域特化响应
- **Orchestrator**：任务规划 → Agent 分派 → 结果汇总，全流程 SSE 推送给前端可视化
- **工具矩阵**：统一接入 **10 个核心工具**（知识库检索、订单查询、物流跟踪、退换货指引、商品搜索、图片识别、语音转文字、天气、计算器、时间）
- **流式输出**：基于 `astream_events` 实现 token 级流式推送，首 token 延迟 <1.5s，Tool 调用过程实时可见

---

## 三、检索阶段

- **文档预处理**：退换货政策、配送规则、商品目录、FAQ 等 Markdown 文档经 `MarkdownHeaderTextSplitter`（标题边界）+ `RecursiveCharacterTextSplitter`（长度兜底）两层切分
- **向量化索引**：ChromaDB + 硅基流动 BAAI/bge-m3（1024 维中英双语 SOTA 嵌入），58 个文档块，持久化到磁盘
- **Adaptive-RAG 策略路由**：LLM 分析查询复杂度 → 简单查询走直接检索，复杂查询分解子问题并行检索
- **Self-RAG 反思**：检索后 LLM 评估充分性，不满足则自动改写查询重试（最多 2 轮）

---

## 四、检索优化

- **混合检索**：BM25 关键词 + BGE-m3 语义向量 双路并行检索，取长补短
- **RRF 融合**：Reciprocal Rank Fusion（k=60）对多源异构检索结果进行融合与去重，语义检索和关键词检索结果互补
- **LLM Rerank**：DeepSeek 对候选文档 1-5 分重排序，过滤低质结果（可替换为 Cohere Rerank API）
- **效果提升**：混合检索相比纯语义检索，精确匹配查询（如"API 访问"）相关度提升约 30%；同义改写查询（如"不花钱的版本能调用接口吗"→"免费版 API 访问"）从 TF-IDF 的字面零匹配提升为语义命中

---

## 五、上下文压缩与记忆管理

- **MemorySaver**：LangGraph 内置 checkpointer，thread_id 级别会话隔离，跨轮记忆上下文
- **会话隔离**：不同 session_id 完全隔离，支持多用户并发，21 个测试用例覆盖 Memory 多轮对话验证
- **Token 预算**：检索结果限制 Top-3 返回，工具结果自动截断，防止上下文膨胀

（128k Token 预算管理 + 3 层渐进压缩为规划中的 v3.3 功能）

---

## 六、Skill + MCP 的可插拔能力体系

- **MCP 协议标准化**：4 个工具以 MCP Server 暴露（HTTP transport），Agent 通过 MCP Client 动态发现并调用
- **工具服务独立化**：McpToolServer 为独立项目（独立 Git 仓库、独立 Docker 部署），零 IntelliDesk 依赖
- **Function Calling 统一接口**：本地 `@tool` 和远程 MCP 工具统一为 LangChain Tool 接口，`USE_MCP` 配置一键切换
- **降级机制**：MCP Server 不可用时自动降级为本地直接模式，不影响核心服务

---

## 七、多模态识别

- **图片识别**：集成阿里百炼 Qwen-VL-Max，用户上传鞋款图片 → VLM 自动识别品牌/型号/品类 → Agent 调 product_search 确认库存 → 返回报价
- **语音输入**：Whisper API 接入，前端 UI 就绪
- **库存校验**：识别后强制交叉查询 product_search，非店内鞋款诚实告知并推荐类似款

---

## 八、兜底与护栏机制

- **MCP 降级**：远程 MCP Server 连接失败时自动切换本地直接模式，Agent 继续服务
- **VLM 降级**：所有 VLM 模型不可用时返回友好提示，引导用户文字描述，不崩溃
- **工具调用边界**：订单查询仅返回 Mock 数据，退换货指引基于知识库检索，不编造政策
- **System Prompt 硬约束**：诚实原则——知识库无信息时告知用户联系人工客服，不猜测不编造

## 九、技术栈总结

| 层级 | 技术 |
|---|---|
| Agent 框架 | LangGraph + LangChain |
| LLM | DeepSeek Chat |
| 意图路由 | Prompt-template + LLM 7 类分类 |
| 检索 | ChromaDB + BGE-m3 + BM25 + RRF + LLM Rerank + Self-RAG |
| 工具协议 | MCP（HTTP transport） |
| 多模态 | Qwen-VL-Max（图片识别）+ Whisper（语音） |
| 后端 | FastAPI + SSE + Pydantic |
| 前端 | Vue 3 + TypeScript + Element Plus + Vite |
| 测试 | pytest（21 用例） |
| 部署 | Docker Compose |
